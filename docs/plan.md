# 블로그 관리자 앱 기획

기획일: 2026-10-13

## 1. 개요

블로그 프로젝트(`playground`)를 관리하는 개인용 관리자 앱이다. 컨텐츠 관리, 오늘 할 일, 사이트 모음, 글감 아이디어, 대시보드를 한 곳에서 본다. 배포 예정.

## 2. 메뉴 구성

사이드바 메뉴 기준이다.

| 메뉴 | 경로 | 내용 |
|---|---|---|
| 대시보드 | `/` | 월간 포스팅 현황, 방치된 임시저장 글, 오늘 할 일 요약 |
| 오늘 할 일 | `/todo` | ToDo 체크리스트 |
| 사이트 모음 | `/reference` | 참고 URL 모음 |
| 글감 아이디어 | `/ideas` | 글로 쓰기 전의 아이디어 메모 |
| 컨텐츠 관리 | `/manage` | 블로그 글 조회, 삭제, 상태 변경 |

스케줄 달력(구글 API 연동)은 범위에서 제외했다.

## 3. 아키텍처

```
[관리 React] ──(JWT)──→ [블로그 API]  글 조회/삭제/상태변경
     │
     └──────────────→ [관리 백엔드] ──→ [관리 DB]  ToDo, 사이트 모음, 글감 아이디어
```

| 구분 | 데이터 | 접근 방식 |
|---|---|---|
| 블로그 글 | 목록 조회, 삭제, 상태 변경 | React → 블로그 API 직접 호출 (JWT) |
| 관리용 데이터 | ToDo, 사이트 모음, 글감 아이디어 | React → 자체 백엔드 |

### 기술 스택

- 프론트: Vite + React 19 + react-router-dom (기존)
- UI: shadcn/ui (radix-nova 스타일) + Tailwind CSS v4. 컴포넌트는 `src/components/ui/`에 추가하고 `@` 별칭(`./src`)을 쓴다. 기존 CSS Modules는 그대로 두고 새 화면부터 Tailwind를 쓴다.
- 백엔드: 이 레포의 `server/` 폴더, Express + Prisma + PostgreSQL
- 인증: 블로그가 발급한 JWT를 같은 `AUTH_SECRET`으로 자체 백엔드에서 검증

### 레포 구조

```
blog-manager/
├─ src/        기존 React (features 단위)
│   └─ features/ dashboard, todos, posts(기존), links, ideas
├─ server/     신규 Express 백엔드 (package.json 별도)
└─ docs/
```

### 인증 흐름

- 블로그 `GET /api/admin/token`이 Google 로그인된 ADMIN 세션에 JWT(HS256, 1시간)를 발급한다.
- 블로그 `requireAdmin()`은 `Authorization: Bearer` 토큰을 받는다.
- 블로그 `src/middleware.ts`는 `ADMIN_APP_ORIGIN` 오리진만 CORS로 허용한다.
- 자체 백엔드도 같은 방식으로 JWT 검증(`role === 'ADMIN'`)과 CORS를 적용한다.
- 토큰 만료 시 블로그 로그인 페이지로 보내 재발급받는다.

### 배포 시 주의

- 두 서버가 `AUTH_SECRET`을 환경변수로 공유한다. 코드와 문서에는 값을 쓰지 않는다.
- 블로그 쪽 `ADMIN_APP_ORIGIN`에 관리 앱 배포 도메인을 등록한다.
- 관리용 DB는 Neon(호스팅 Postgres)을 쓴다. 블로그 DB와는 별도 프로젝트/database로 분리한다.
- Neon 연결 문자열은 풀링용(`DATABASE_URL`)과 마이그레이션용 직접 연결(`DIRECT_URL`)을 나눠 환경변수로 둔다. 값은 코드와 문서에 쓰지 않는다.

## 4. 페이지 기획

### 4.1 컨텐츠 관리 (블로그 글)

- 블로그 API로 목록 조회, 삭제, 상태 변경(`published`, `status`)을 한다.
- 글 작성과 수정은 외부(블로그)에서 하고, 이 앱은 해당 URL로 이동만 한다.
- 블로그 글 종류별 엔드포인트가 다르다: `/api/projects`, `/api/lab`, `/api/devlog` (`PROJECT`, `LAB`, `DEV_LOG`).
- 임시저장 글은 `?draft=true`로 조회한다 (관리자 전용).
- 칸반 보기는 후순위 옵션이다.

### 4.2 오늘 할 일 (ToDo)

- 필드: 제목, 상태(TODO/DOING/DONE), 마감일, 우선순위
- UI: 체크리스트(체크하면 DONE, 해제하면 TODO) + 마감일/우선순위 필터
- 후순위: 태그, 블로그 글 연결, 칸반 보기

### 4.3 사이트 모음 (참고 URL)

- 필드: 제목, URL, 카테고리, 한 줄 설명, 즐겨찾기
- 카테고리 고정 4종: AI, Design, Frontend, Backend (enum)
- 입력은 수동. OG 태그 자동 채움은 하지 않는다.
- UI: 카테고리 필터 + 검색

### 4.3.1 바로가기 (자주 쓰는 사이트)

- 사이트 모음(DB 관리)과 별개로, 자주 여는 사이트를 사이드바 하단 "바로가기" 그룹에 고정 노출한다.
- 데이터는 DB 없이 `src/layouts/side-nav/quick-links.ts`의 상수 배열로 관리한다 (`{ label, url, icon }`). 수정은 코드에서 한다.
- 클릭 시 새 탭으로 연다 (`target="_blank"`, `rel="noopener noreferrer"`).
- 사이드바가 접힌 상태에서는 아이콘 + 툴팁으로 표시한다.

| 그룹 | 사이트 | URL |
|---|---|---|
| 영상 | 유튜브 | https://www.youtube.com |
| AI | ChatGPT | https://chatgpt.com |
| AI | Gemini | https://gemini.google.com |

- Claude는 프롬프트로 직접 사용하므로 제외한다.
- 후보(확정 전, 필요한 것만 선택):
  - 블로그 운영: 내 블로그 사이트, 블로그 배포 대시보드(Vercel 등), Google Search Console, Google Analytics, 네이버 서치어드바이저
  - 개발: GitHub, MDN, Can I use, npm
  - 디자인/UI: Figma, shadcn/ui 문서, Tailwind CSS 문서, Lucide 아이콘
  - 정리/기타: Notion, Google Drive

### 4.4 글감 아이디어

- 컨텐츠 관리는 이미 올라간 글만 다루므로, 글로 쓰기 전의 아이디어를 담는 메뉴다.
- 필드: 제목, 메모, 상태(`todo` 대기 / `doing` 진행 / `done` 완료), 연결할 글 URL(선택)
- 글감 아이디어 페이지에서 항목의 상태를 `doing`으로 바꾸면 "진행"으로 선택한 것이고, 대시보드 "아이디어 진행" 카드에 제목이 표시된다.
- UI: 상태별 필터 + 목록, 빠른 추가 입력창
- 후순위: 사이트 모음 항목과의 연결, 태그

### 4.4.1 AI 아이디어 대화

- 대시보드 상단 "아이디어 생성" 영역은 AI와 메시지를 주고받는 대화형 UI다. 대화하며 글감을 다듬고, 대화 전체를 요약해 글감 아이디어로 저장한다.
- 제공자는 Gemini(무료 티어)로 확정한다. 무료 한도(요청 수, 모델 목록)는 수시로 바뀌므로 코드에 고정하지 않고 AI Studio에서 확인한다.
- 첫 버전은 대화형이되 응답을 한 번에 받는다. 스트리밍은 후순위다.
- 대화 내용은 서버에 저장하지 않고 화면 안에서만 유지한다 (새로고침하면 초기화). 저장하는 것은 "대화 저장"으로 만든 요약 글감뿐이다. 대화 원문은 저장하지 않는다.

**화면**
- 대화 영역(고정 높이, 내부 스크롤) + 하단 입력창과 보내기 버튼
- 사용자 메시지는 오른쪽, AI 메시지는 왼쪽 말풍선. 응답 대기 중에는 "생각하는 중" 표시, 전송 버튼 비활성화
- AI 메시지에는 제안 카드(`{ title, summary, type, reason }`)가 붙을 수 있다. 카드는 표시 전용이며 개별 저장 버튼은 없다.
- 카드 우측 상단 "대화 저장" 버튼으로 저장한다. 대화가 비어 있거나 응답 대기 중에는 비활성화한다.

**흐름**
1. 사용자가 주제나 질문을 보낸다 (비어 있는 대화에서는 최근 글 흐름에 맞춘 제안을 요청할 수 있다).
2. AI가 답변과 함께 필요하면 아이디어 제안 카드를 돌려준다.
3. 사용자가 후속 메시지로 방향을 좁히거나 제목, 개요를 다듬는다.
4. "대화 저장"을 누르면 서버가 대화 이력을 요약해 `{ title, memo, type }` 초안을 만든다.
5. 미리보기 모달에서 제목, 메모, 종류를 수정하고 저장하면 글감 아이디어(상태: `todo`)에 추가된다.

**AI에 함께 넘기는 맥락** (서버가 조합)
- 대화 이력 (최근 N개 메시지만. 길이 제한)
- 최근 발행 글 제목/종류 (주제 반복 방지)
- 방치된 임시저장 글 (이어 쓸 만한 것 제안)
- 기존 글감 아이디어 (중복 방지)

**구조와 규칙**
- `POST /api/ideas/chat`(자체 백엔드)이 요청의 대화 이력으로 Gemini를 호출하고 `{ text, suggestions? }`를 돌려준다. 프론트에서 직접 호출하지 않는다.
- `POST /api/ideas/summarize`는 대화 이력을 요약해 `{ title, memo, type }`을 돌려준다. 저장은 기존 글감 아이디어 생성 API를 쓴다.
- AI 호출은 백엔드의 한 모듈(`ai-client`)로 분리해 제공자를 바꾸기 쉽게 한다.
- API 키는 백엔드 환경변수 `GEMINI_API_KEY`로만 둔다. 값은 코드와 문서에 쓰지 않는다.
- ADMIN JWT 검증을 거치고, 호출 횟수, 대화 이력 길이, 메시지 길이를 제한한다.
- 한도 초과(429) 시 "잠시 후 다시 시도" 안내를 대화창에 보여 준다.
- 구현 시점은 글감 아이디어 CRUD(5단계) 이후다. 그 전까지 UI는 가짜 응답으로 퍼블리싱한다 (`idea-generator-card.tsx`).

### 4.5 대시보드

| 위젯 | 데이터 출처 | 표시 |
|---|---|---|
| 월간 포스팅 현황 | 블로그 API | 이번 달 주차별 막대그래프 + 월 합계, 이전/다음 달 이동(선택) |
| 방치된 임시저장 글 | 블로그 API | `updatedAt` 오름차순 3개, 기간 제한 없음, 전체 보기 링크 |
| 오늘 할 일 요약 | 자체 백엔드 | 미완료 개수, 마감 임박 항목 |
| 아이디어 진행 | 자체 백엔드 | `doing` 상태 아이디어 제목 1개(여러 개면 "외 N개"). 없으면 "대기중인 아이디어 N개"(`todo` 개수) |

- 주차 기준: 1~7일 1주차, 8~14일 2주차, 15~21일 3주차, 22~28일 4주차, 29일 이후 5주차
- 날짜 기준: `createdAt` (블로그 `Post`에 발행일 필드가 없음)
- 지나지 않은 주차는 빈 막대나 회색으로 표시한다.
- 차트 라이브러리 없이 막대를 직접 그린다.

## 5. 구현 순서

| 단계 | 내용 | 이유 |
|---|---|---|
| 1 | 컨텐츠 관리 마무리 (삭제, 상태 변경) + 사이드바 공통 레이아웃 | 이미 시작됨. 블로그 API만 필요 |
| 2 | 자체 백엔드 뼈대 (Express, Prisma, DB 연결, JWT 검증, CORS) | 이후 모든 기능의 기반 |
| 3 | 오늘 할 일 | 백엔드 첫 기능. 구조 검증용 |
| 4 | 사이트 모음 | ToDo와 비슷한 CRUD |
| 5 | 글감 아이디어 | 같은 CRUD 구조 |
| 6 | AI 아이디어 대화 (Gemini) | 백엔드와 글감 아이디어 저장이 필요 |
| 7 | 대시보드 데이터 연동 | 블로그 글, ToDo, 아이디어 데이터가 필요. UI 퍼블리싱은 먼저 완료 |

## 6. 남겨 둔 결정과 후순위

- 정확한 발행일이 필요하면 블로그 `Post`에 `publishedAt`을 추가한다.
- 칸반 보기, ToDo 태그, 블로그 글 연결은 후순위다.
- 사이트 모음의 OG 자동 채움과 카테고리 가변화는 필요해지면 추가한다.
- 스케줄 달력(구글 API)은 제외했고, 필요해지면 별도로 다시 기획한다.
