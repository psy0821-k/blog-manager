## 현재 상태

- 완료(단계 0·1·2·3): 대시보드 실데이터 3종, **로그인 연동**(블로그 JWT, 가드, 재로그인, 로그아웃, 실패 안내, 개발용 토큰 화면 제거), **바로가기 블로그 링크**, **컨텐츠 관리**(발행됨/임시저장 보기, 편집 링크, 발행 ↔ 임시저장 전환, 확인 후 삭제). 모두 `main`에 반영됐고 이슈 #4~#7, #12~#15는 닫혔다.
- 블로그 쪽 대기: 랩의 쓰기 API(`PATCH`/`DELETE`)가 관리 앱 토큰을 받도록 하는 변경(블로그 PR). 배포 전에는 랩 글 전환·삭제가 거부된다. 프로젝트·개발일지는 지금도 동작한다.
- 미구현: 자체 백엔드(`server/`), `/todo`, `/reference`, `/ideas`, AI 대화(가짜 응답)

## 추가한 작업 (요청 목록 외)

- **단계 0 사전 정리**: ✅ PR #3 머지 후 단계별 브랜치로 진행했다. `feature/login` 위에 `feature/content-management`를 쌓는 바람에 `main` 반영이 늦어졌으니(PR #21, #22로 반영), 다음 단계부터는 `main`에 먼저 반영한 뒤 시작한다.
- **API 쓰기 지원**: ✅ `api-client.ts`가 `apiGet`·`apiPatch`·`apiDelete`를 한 요청 코어로 공유한다. POST는 자체 백엔드 단계(5~7)에서 필요해질 때 추가한다.
- **E2E 보강**: ✅ 로그인·컨텐츠 관리 E2E가 있다. 임시 저장·주차별 성실도 카드 E2E는 아직 없다.
- **E2E 환경 개선(제안)**: E2E가 5173의 개발 서버를 재사용해 더미 로그인 주소가 적용되지 않는 문제가 반복됐다. Playwright가 전용 포트로 자체 서버를 띄우게 하면 개발 서버를 끄지 않고 돌릴 수 있다(테스트의 앱 주소 상수도 함께 바꿔야 한다).
- **보안**: 단계마다 `security-rules`와 `security-review`를 적용한다. 특히 `GEMINI_API_KEY`, `DATABASE_URL`, `AUTH_SECRET`은 `.env.example`에 키 이름만 두고 값은 커밋하지 않는다.
- **오류·빈 상태 UI 공통화**: 목록 화면마다 로딩·에러·빈 상태가 반복되므로, 단계 5에서 두 번째로 쓰일 때 공통 컴포넌트로 뽑는다 (미리 만들지 않음, YAGNI).
- **CI**: GitHub Actions로 lint, 테스트, 빌드를 PR마다 실행 (단계 4 전후).
- **번들 크기**: 빌드 시 500kB 경고가 있다. 라우트 단위 `lazy` 분할은 단계 9 전에 한다.
- **문서 갱신**: 단계가 끝날 때마다 `CLAUDE.md`의 아키텍처·"가짜 데이터" 설명을 실제와 맞춘다.

## 후속 과제 (로그인·컨텐츠 관리에서 남긴 것)

- 블로그 `slug`가 `.`·`..`이 될 수 없다는 점에 기대고 있다. 방어 심화로 `buildPostPath`·`buildPostEditUrl`에서 `.`·`..` slug를 거부할 수 있다.
- 카테고리 Select 변경 경로는 코드상 `draft`를 보존하고 `page`를 지우지만 단위 테스트와 E2E가 없다(jsdom 제약).
- `sanitizeReturnPath`가 탭·개행이 든 경로를 걸러내지 않는다(현재 악용 경로 없음). `saveReturnPath`도 저장 시에는 검증하지 않는다.
- 삭제 대화상자가 닫히는 애니메이션 중 설명에 「null」이 잠깐 보일 수 있다(미관).
- 삭제 중 같은 글의 전환 버튼이 비활성인지 검증하는 통합 테스트를 보강한다.
- `shadcn`이 `dependencies`에 있어 `npm audit`에서 직접 의존성 high로 잡힌다(CLI 도구, 번들 미포함). `devDependencies`로 옮기는 것을 검토한다.
- 오류·빈 상태 UI를 두 번째 사용처(단계 5)에서 공통 컴포넌트로 뽑고, `usePostActions`의 처리 상태 로직도 범용 mutation 훅으로 추출할지 그때 판단한다.
