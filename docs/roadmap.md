## 추가한 작업 (요청 목록 외)

- **단계 0 사전 정리**: PR #3 머지 후 `main`을 기준으로 새 브랜치를 딴다. 지금처럼 브랜치가 쌓이면 충돌이 커진다.
- **API 쓰기 지원**: `apiGet`이 GET만 지원한다. 삭제, 상태 변경, CRUD를 위해 POST/PATCH/DELETE를 지원하도록 `api-client.ts`를 확장한다 (단계 3 시작 전).
- **E2E 보강**: 임시 저장·주차별 성실도 카드 E2E가 없다. 단계 1 이후 로그인 E2E도 추가한다.
- **보안**: 단계마다 `security-rules`와 `security-review`를 적용한다. 특히 `GEMINI_API_KEY`, `DATABASE_URL`, `AUTH_SECRET`은 `.env.example`에 키 이름만 두고 값은 커밋하지 않는다.
- **오류·빈 상태 UI 공통화**: 목록 화면마다 로딩·에러·빈 상태가 반복되므로, 단계 5에서 두 번째로 쓰일 때 공통 컴포넌트로 뽑는다 (미리 만들지 않음, YAGNI).
- **CI**: GitHub Actions로 lint, 테스트, 빌드를 PR마다 실행 (단계 4 전후).
- **번들 크기**: 빌드 시 500kB 경고가 있다. 라우트 단위 `lazy` 분할은 단계 9 전에 한다.
- **문서 갱신**: 단계가 끝날 때마다 `CLAUDE.md`의 아키텍처·"가짜 데이터" 설명을 실제와 맞춘다.
